# Learning rate (LR)

## Что такое LR

**Learning rate (LR)** — это **шаг, с которым оптимизатор обновляет веса модели**.  Один из самых критичных гиперпараметров. Я объясню, что это, как влияет, и как выбирать для твоей Transformer-модели на финансовых данных.

В формуле градиентного спуска:

[
w_{t+1} = w_t - \text{LR} \cdot \nabla_w L(w_t)
]

* **слишком большой LR** → вес прыгает через минимум, loss колеблется или растёт → обучение нестабильно
* **слишком маленький LR** → обучение очень медленное, может застрять в локальном минимуме


## Типичные значения LR

| Оптимизатор            | Начальный LR |
| ---------------------- | ------------ |
| SGD (классический)     | 0.01–0.1     |
| Adam / AdamW           | 1e-3 – 3e-4  |
| Adam с большим D_MODEL | 3e-4 – 1e-4  |

> Для твоей Transformer-модели с `D_MODEL=256` и 1.2 млн примеров обычно **Adam, lr=1e-3** — хорошая отправная точка.


## Почему LR критичен для трансформеров

1. **Глубокие слои (NUM_LAYERS=4)** → градиенты могут **исчезать или взрываться**
2. **Large D_MODEL** → большие веса → слишком высокий LR может "сносить" модель
3. **Financial data** → шумная, нестабильная → маленький LR помогает стабильно подстраиваться под паттерны


## LR для разных компонентов модели

* **Input projection + Transformer** → чувствительны к LR
* **Output head (6 выходов)** → немного менее чувствителен, но всё равно часть общей сети
* **Рекомендация**: один LR для всей сети сначала, потом можно **split LR** (encoder и head раздельно)


## LR schedule (рекомендую)

Использование статического LR — норм для старта, но лучше **schedule**, особенно для трансформеров:

1. **Warmup + Cosine decay**

```text
- lr_start = 0
- lr_max = 1e-3
- warmup_steps = 1000
- decay → постепенно уменьшаем до 0
```

2. **ReduceLROnPlateau**

* уменьшает LR, если loss не улучшается
* полезно для шумных финансовых рядов

3. **CyclicLR / OneCycle**

* быстро разгоняет обучение в начале
* хорошо помогает выходить из локальных минимумов


## Практические советы

1. Начни с **lr = 1e-3** для Adam
2. Проверь **loss на первых 100–500 шагах**:

   * Если loss резко растёт → уменьшай LR (например, 3e-4)
   * Если loss падает медленно → можно увеличить LR до 2e-3
3. Для больших моделей (`D_MODEL=512, NUM_LAYERS=6`) обычно **уменьшают LR** до 1e-4


## Контроль LR в PyTorch

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-6)

# с LR scheduler
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=50)
```

* `T_max` — количество эпох для одного цикла
* Можно комбинировать с warmup через `LambdaLR`


Далее составим **практическую таблицу с рекомендованными LR** для Transformer-модели, учитывая:

* D_MODEL (размер эмбеддинга)
* NUM_LAYERS (глубина трансформера)
* Batch size (объём градиента)
* Тип optimizer: Adam / AdamW
* Предполагаемая последовательность свечей: SEQ_LEN=10–20


## Основные правила выбора LR

1. **Малые модели** (D_MODEL≤256, NUM_LAYERS≤4) → LR ≈ 1e-3
2. **Средние модели** (D_MODEL=256–512, NUM_LAYERS=4–6) → LR ≈ 3e-4 – 1e-3
3. **Большие модели** (D_MODEL>512, NUM_LAYERS>6) → LR ≈ 1e-4 – 3e-4
4. **Малый batch size** → уменьшаем LR, т.к. градиенты шумнее
5. **Большой batch size** → можно слегка увеличить LR

> Для финансовых временных рядов лучше **чуть меньше**, чем рекомендуют классические NLP модели — шумные данные любят стабильный градиент.


## Таблица рекомендуемых LR

| D_MODEL | NUM_LAYERS | Batch size | Рекомендованный LR (Adam/AdamW) | Комментарий                              |
| ------- | ---------- | ---------- | ------------------------------- | ---------------------------------------- |
| 128     | 2          | 128–512    | 1e-3                            | Маленькая модель, быстро обучается       |
| 256     | 4          | 128–512    | 1e-3                            | Отличный старт для твоих данных          |
| 256     | 4          | 64         | 5e-4                            | Меньший batch → меньше LR                |
| 256     | 6          | 128–512    | 5e-4 – 8e-4                     | Глубже, чуть осторожнее                  |
| 512     | 4          | 128–512    | 3e-4 – 5e-4                     | Широкие эмбеддинги → стабильный градиент |
| 512     | 6          | 128–512    | 1e-4 – 3e-4                     | Большая, глубокая → медленное обучение   |
| 512     | 8          | 256–1024   | 1e-4                            | Очень большая модель → очень осторожно   |


## Рекомендации по LR schedule

1. **Warmup + Cosine decay**:

   * Warmup: LR растёт от 0 → LR_max в первые 500–1000 шагов
   * Потом плавный decay → LR_min ≈ 0
   * Очень помогает Transformer на шумных данных

2. **ReduceLROnPlateau**:

   * Если loss не падает 3–5 эпох → уменьшить LR в 2 раза

3. **OneCycleLR** (экспериментально)

   * Полезно для коротких обучений, быстро находит хорошие minima


## Практический пример для твоей модели

* D_MODEL=256, NUM_LAYERS=4, SEQ_LEN=10, batch_size=512
* Оптимизатор: Adam
* LR старт: 1e-3
* Scheduler: CosineAnnealingLR, T_max=50 эпох, минимальное LR=1e-5

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-6)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=50, eta_min=1e-5)
```

> Batch size 512 + миллион примеров → обучение стабильное и не слишком шумное.
