# Управление опубликованными моделями

> Тип: операционное руководство. Просмотр моделей и отслеживание их удаления.

Каждая опубликованная модель хранится в `models/` и имеет запись в PostgreSQL.
Команды ниже показывают доступные модели, запрашивают удаление и позволяют
дождаться его завершения. Удаление необратимо.

Публичный [каталог моделей](../../app/contracts/model_catalog/v9/README.md)
даёт клиенту доступ только к моделям его владельца и только для чтения.
Административное удаление выполняется через CLI. Перед работой проверьте
версию базы по [руководству миграций](database-migrations.md).

Устройство хранилища описано в [руководстве сервиса](flight-service.md#хранение-данных),
причины двухэтапного удаления — в [ADR 0016](../adr/0016-hard-delete-published-models.md).

## Просмотреть доступные модели

```bash
./.venv/bin/python ./app/main.py models list
```

Команда показывает модели в состоянии `AVAILABLE`: точный `MODEL REF`,
владельца, метку, поколение, состояние и время создания. Поколение — отдельная
неизменяемая опубликованная версия модели; `MODEL REF` указывает именно на неё.

Публичный каталог использует те же записи PostgreSQL. Просмотр списка
не читает контрольную точку. Запрос detail дополнительно проверяет её
метаданные и полный SHA-256 файла в пределах установленного лимита.
Метрики OpenSearch и наличие файлов сами по себе не добавляют модель в каталог.

Перед удалением выберите точный `MODEL REF`. Команда принимает этот
идентификатор, а не метку модели.

## Запросить удаление

```bash
./.venv/bin/python ./app/main.py models delete <MODEL_REF>
```

При успехе команда выводит:

```text
Model: <MODEL_REF>
State: DELETING
```

Запрос выполняется в транзакции:

- блокирует новые задания предсказания и обучения с `publishedModel`
  от этой версии модели;
- отклоняется, если на неё ссылается незавершённое задание предсказания
  или обучения с `publishedModel`;
- переводит модель в `DELETING`.

Перед командой убедитесь, что выбрана нужная версия и клиенту она больше
не нужна. Команды отмены удаления нет.

## Дождаться физического удаления

После фиксации запроса модель сразу исчезает из обычного `models list`.
Фоновое обслуживание работающего сервиса:

1. удаляет каталог `models/{modelRef}`;
2. удаляет запись модели из PostgreSQL;
3. сохраняет минимальную запись `DELETED` с идентификатором и временем событий.

Состояние удаления видно отдельной командой:

```bash
./.venv/bin/python ./app/main.py models list --deleted
```

Она показывает текущие `DELETING` и завершённые `DELETED`. Для `DELETING`
колонка `DELETED AT` пуста; после успешной очистки в ней появляется время.

Ошибка файловой системы оставляет модель в `DELETING`, и сервис повторяет
очистку. Если состояние не меняется, проверьте логи сервиса и доступность
`models/`. Ручное удаление строки PostgreSQL нарушает порядок очистки.

## Повторные операции и история

До завершения очистки повторный `models delete` возвращает `DELETING`.
После неё запись модели уже удалена, поэтому команда возвращает
`model generation not found`.

История содержит только владельца, метку, поколение, идентификатор модели
и время событий. Пути и хеши контрольных точек, определения модели и полные
метаданные не сохраняются. Восстановить модель по этой записи нельзя.
Номер поколения остаётся монотонным и повторно не используется.

Удаление модели не отменяет ожидающую доставку метрик и не удаляет документы
из OpenSearch. У показателей обучения отдельный срок хранения.

## Проверить удаление

Эту проверку выполняют только для версии модели, которую разрешено физически
удалить:

1. Найдите точный `MODEL REF` через `models list`.
2. Убедитесь, что нет незавершённых заданий предсказания или обучения
   с `publishedModel`, ссылающихся на эту версию.
3. Выполните `models delete <MODEL_REF>` и проверьте `State: DELETING`.
4. Убедитесь, что модель исчезла из обычного `models list`.
5. Наблюдайте `models list --deleted`, пока состояние не станет `DELETED`
   и не появится `DELETED AT`.
