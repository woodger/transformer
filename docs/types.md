# Транспортная архитектура

**Node.js → Python (`fit-stream`)**

```
Node.js
  └─ framed Arrow IPC file payloads → stdin
        │
        ▼
Python
  └─ 8-byte big-endian length + pyarrow.ipc.RecordBatchFileReader(payload)
```

* Node.js пишет в stdin Python-процесса последовательность frames.
* Каждый frame: `8 bytes unsigned big-endian payload length`, затем payload.
* Каждый payload — самостоятельный Arrow IPC file с колонками `src` и `tgt`.
* Python читает frames через `iter_framed_arrow()` и обучается на каждом
  непустом payload.
* используется **`execa`**
* никаких временных файлов

**Python → Node.js**

Схема симметричная и тоже основана на **Arrow IPC Stream**:

```
Python
  └─ Arrow IPC Stream → stdout
        │
        ▼
Node.js
  └─ apache-arrow RecordBatchReader (stdin)
```

# Архитектура модели

---

# ✅ 1. **LSTM / GRU**

**Классика для временных рядов.**

### 🔹 Что это такое?

Это реккурентные нейросети. Они обрабатывают последовательность "шаг за шагом".

**LSTM** — дольше держит память, но тяжелее.
**GRU** — проще, быстрее, даёт похожие результаты.

### 🔹 Применение:

* Прогноз следующей цены или направления
* Короткие или средние временные окна (20–200 свечей)
* Когда важен порядок и плавность временного ряда

### ✅ Плюсы:

✔ Подходят почти всегда
✔ Простая реализация
✔ Легко обучить на GPU/CPU
✔ Требуют меньше данных, чем трансформеры

### ❌ Минусы:

✖ Медленные при длинных последовательностях
✖ Память ограничена — теряют дальний контекст

---

# ✅ 2. **TCN — Temporal Convolutional Networks**

**Альтернатива LSTM, но на свёртках.**

### 🔹 Как работают?

Вместо реккурентности — 1D-свёртки с «dilated» (растянутыми) слоями.
Охватывают длинный контекст быстрее и параллельно.

### 🔹 Применение:

* Финансовые таймсерии
* Выявление паттернов
* Длинные окна (100+ свечей)

### ✅ Плюсы:

✔ Быстрее LSTM (параллелизация)
✔ Лучше ловит долгие зависимости
✔ Хорошо работает с последовательностями фиксированной длины

### ❌ Минусы:

✖ Чувствительны к архитектуре (размер ядра, дилатация)
✖ Чуть сложнее отлаживать

---

# ✅ 3. **1D Conv + LSTM (гибрид)**

**Когда хочешь вытащить паттерны + учесть временной порядок.**

### 🔹 Как работает?

```
Свёртки (Conv1D) → вытаскивают локальные паттерны
↓
LSTM / GRU → видит динамику во времени
```

### 🔹 Применение:

* Свечи + объём
* Паттерны вроде «двойная вершина», «импульс», «коррекция»
* Обогащённые фичи (индикаторы, дельта-профиль)

### ✅ Плюсы:

✔ Ловит и форму свечей, и динамику
✔ Стабильнее, чем чистые LSTM
✔ Часто работает лучше на бирже, чем LSTM/TCN отдельно

### ❌ Минусы:

✖ Нужно больше данных
✖ На проде тяжелее поддерживать, чем LSTM

---

# ✅ 4. **Transformer**

**Топовый вариант, если есть много данных.**

### 🔹 Как работает?

Вместо реккурентности — механизм внимания (self-attention).
Модель сама решает, какие части истории важны.

### 🔹 Применение:

* Прогноз на большие промежутки
* Много фич (цена, объём, стакан, индикаторы)
* Длинные окна (200–2000 свечей)

### ✅ Плюсы:

✔ Улавливает сложные нелинейности
✔ Поддерживает очень длинный контекст
✔ Легко масштабировать

### ❌ Минусы:

✖ Требует много данных
✖ Тяжелее обучать
✖ Медленнее инференс, чем TCN/Conv+LSTM

# ✅ Что выбрать под задачу с свечами?

| Архитектура   | Для начала | Средние данные | Большие данные | Скорость  | Контекст |
| ------------- | ---------- | -------------- | -------------- | --------- | -------- |
| LSTM / GRU    | ✅          | ✅              | ⚠️             | Средняя   | Малый    |
| TCN           | ✅          | ✅              | ✅              | Быстрая   | Средний  |
| Conv1D + LSTM | ✅          | ✅              | ✅              | Средняя   | Средний  |
| Transformer   | ⚠️         | ✅              | ✅✅             | Медленная | Большой  |

---

# ✅ Быстрый старт:

**Можно начать с LSTM или Conv1D + LSTM.**
Когда появится больше данных и запрос на мощность — переходи на TCN или Transformer.
