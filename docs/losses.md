# Функции потерь и регуляризация

> Тип: справочник. Формулы потерь, веса компонентов и регуляризация энтропией.

Функция потерь задаётся в `ModelContract`: для каждой цели выбирается прямая
компонента, а при необходимости добавляются вспомогательные. Здесь описаны
их формулы и влияние на обучение. Точные допустимые поля определены в
[спецификации целей и потерь](../app/contracts/semantic/v7/README.md).
Имена целей не задают отдельного поведения функции потерь.

## Цели и выходные значения

Для каждой цели в заданном порядке объявляются преобразование входа функции
потерь и преобразование предсказания. Оба применяются к одному исходному
выходному значению модели. Поддерживаются `Identity`, `Tanh` и `Sigmoid`.
Целевые значения `y` и публичные предсказания передаются через Arrow как
конечные Float32. Тип промежуточных тензоров выбирает Transformer.

Для конечных значений `observedConstraint` можно опустить; закрытый интервал
задаётся явно. Оператор потерь указывается в прямой компоненте соответствующей
цели и не определяется по её имени.

## Прямые компоненты потерь

Для одной цели `T`:

```text
SmoothL1:
  mean(SmoothL1(lossEstimate[T], observed[T]))

BinaryCrossEntropyWithLogits:
  mean(BCEWithLogits(rawLogit[T], observedProbability[T]))

PositiveClassWeightedBinaryCrossEntropyWithLogits:
  mean(-positiveClassWeight * observedBinary[T] * log(sigmoid(rawLogit[T]))
       - (1 - observedBinary[T]) * log(1 - sigmoid(rawLogit[T])))

LogMSE:
  mean((log(positiveEstimate[T] + 1e-6)
        - log(nonNegativeObserved[T] + 1e-6))²)
```

`BinaryCrossEntropyWithLogits` получает исходный логит через `Identity` и
целевые значения в `[0, 1]`. `LogMSE` получает оценку через `Sigmoid` и требует
замкнутого неотрицательного интервала наблюдений. У каждой цели ровно одна
прямая компонента.

`PositiveClassWeightedBinaryCrossEntropyWithLogits` предназначен только для
бинарных меток. Он требует точный `ClosedInterval [0,1]`, вход через `Identity`,
публичное преобразование `Sigmoid`, конечный `positiveClassWeight > 0` и метки
Float32 ровно `0` или `1`. При `positiveClassWeight = 1` потери совпадают с
BCEWithLogits для бинарных меток. Обычная BCE также допускает дробные метки.
Вес положительного класса применяется до усреднения `GlobalRowMean`; вес
компоненты `weight` — после него, при сложении `WeightedSum`.

Для взвешенной бинарной классификации публичное предсказание равно:

```text
sigmoid(rawLogit[T] - log(positiveClassWeight))
```

Это вероятность с поправкой на вес класса для распределения переданных строк.
Поправка не гарантирует калибровку на других данных. Обучающие MAE и RMSE
вычисляются по этому предсказанию; прямые и суммарные потери остаются
взвешенными значениями обучающего прохода.

## Внутренние ресурсы и вспомогательные компоненты

`PositiveScalarPerObservation` — внутренний положительный выход модели,
для которого можно вычислять градиент. Его описание сохраняется в контрольной
точке. Несколько компонент могут использовать его по одному непрозрачному
идентификатору ресурса; клиент не получает это значение в предсказаниях.
`GaussianNLL` передаёт через него градиент. `RiskAdjustedExpectedValue`
использует масштаб с отключённым градиентом.

```text
GaussianNLL:
  variance = scale² + 1e-6
  mean(0.5 * ((observed - location)² / variance + log(variance)))

ExpectedValue:
  -mean(positiveProbability - negativeProbability)

RiskAdjustedExpectedValue:
  delta = positiveProbability - negativeProbability
  -mean(delta - riskPenalty * stopGradient(scale) * abs(delta))
```

`ExpectedValue` и `RiskAdjustedExpectedValue` можно использовать вместе. Веса
всех компонент положительны. Каждая компонента усредняется по правилу
`GlobalRowMean`, затем результаты складываются с весами по правилу
`WeightedSum`. Эти правила фиксированы и не повторяются в каждом документе
функции потерь.

## Confidence penalty

`BernoulliConfidencePenalty` добавляется как вспомогательная компонента для
цели с публичным `Sigmoid`, в том числе при взвешенной бинарной BCE. Его
положительный вес `b` даёт вклад `-b * mean(H(p))`, где
`H(p) = -p * ln(p) - (1 - p) * ln(1 - p)`. Для взвешенной бинарной BCE
`p = sigmoid(z - ln(positiveClassWeight))`. Расчёт энтропии от исходного
`sigmoid(z)` менял бы оптимум. Если компонента не объявлена, регуляризации нет.

При весе прямой компоненты `a` получается `a * BCE - b * H(p)`, поэтому
относительный коэффициент `lambda = b / a`. Максимизация энтропии тянет
вероятность к `0.5` и может завышать оценку редкого события. Поправка на вес
класса не устраняет это смещение. Коэффициент выбирается на отложенных данных;
регуляризатор не гарантирует калибровку или улучшение сигнала.

Transformer вычисляет отрицательную энтропию через `sigmoid` и `logsigmoid`
конечного логита с поправкой на вес класса. Float16/bfloat16 переводятся
в float32. Вероятности не обрезаются, градиент не отключается. Статистика
вспомогательных потерь содержит отрицательную энтропию без веса; суммарные
потери учитывают её взвешенный вклад. Отрицательное значение этой компоненты
допустимо.

## Entropy penalty

`BernoulliEntropyPenalty` — отдельная вспомогательная компонента с положительным
весом `b`, добавляющая `+b * mean(H(p))`. При весе прямой компоненты `a` сумма равна
`a * BCE + b * mean(H(p))`, относительный коэффициент `lambda = b / a`.
Для отключения достаточно не объявлять компоненту. Собственных параметров
у оператора нет.

Роль `probability` ссылается на существующую цель с публичным `Sigmoid`.
Используется тот же логит с поправкой на вес класса и устойчивый расчёт
энтропии, что и у confidence penalty, с противоположным знаком. Прямая BCE
не меняется. Статистика вспомогательных потерь содержит положительную
`mean(H(p))` без веса; вес применяется только к суммарным потерям и градиенту.

Для публичного логита `l` градиент энтропии равен `-l * p * (1 - p)`. Минимизация
усиливает уверенность в обе стороны; при `l = 0` вклад равен нулю. Уверенность
может быть ошибочной, а редкое событие — дополнительно подавляться. Оператор
не гарантирует калибровку. Сравнивайте обучения с нуля на одинаковых данных и
параметрах, оценивая энтропию вместе с BCE на отложенных данных, Brier, PR-AUC
и калибровкой.

Объявление компоненты и её вес входят в определение функции потерь и модели.
Их изменение несовместимо с восстановлением и обучением от опубликованной
модели. Порядок целей и выбор эпохи по прямым компонентам сохраняются.
Коэффициент `0.1` в примерах — выбор эксперимента, а не значение по умолчанию.

## Диагностика

Transformer выбирает эпоху по взвешенным прямым потерям. Наблюдение
взаимодействий градиентов включается отдельно и не меняет градиенты, веса,
совместимость функции потерь или порядок выходных значений. Формат отчёта
описан в [спецификации показателей обучения](../app/contracts/training_telemetry/v4/README.md).
