# Обучение, контрольные точки и восстановление

> Тип: справочник. Как проходит обучение и когда его можно восстановить после сбоя.

Обучение выполняется в отдельном процессе Worker. Сервис принимает данные,
сохраняет результаты и при допускающем повтор сбое может восстановить Worker
из контрольной точки. Ниже описаны порядок обработки данных и условия такого
восстановления.

## Определение модели и обучение

Запрос `fit` передаёт описание целей, функции потерь и размеров данных.
Transformer проверяет документ по спецификации, строит внутреннюю конфигурацию
модели и сохраняет идентификаторы совместимости D1. Порядок целей задаёт
порядок выходных значений. Имена целей не влияют на выбор модели или функции
потерь.

Позиционное кодирование поддерживает нечётную `hiddenWidth` и всю объявленную
длину `seqLen`. При `seqLen <= 5000` размер буфера контрольной точки остаётся
прежним; для более длинной последовательности буфер создаётся по `seqLen`.

Для каждого выходного значения Worker применяет объявленные преобразования
входа функции потерь и результата предсказания. Формулы, внутренние ресурсы и
правила вычисления градиентов описаны в [справочнике функций потерь](./losses.md)
и [спецификации целей и потерь](../app/contracts/semantic/v7/README.md).
Правила обучения задаются отдельно от определения модели. При включённом
выборе лучшей эпохи оценка учитывает только взвешенные прямые компоненты потерь;
вспомогательные компоненты в неё не входят.

Пропуски признаков обрабатываются по `missingValuePolicy`:

- `strict`: временной шаг исключается, если отсутствует хотя бы один признак;
- `relaxed`: шаг исключается, только если отсутствуют все признаки; модель
  также получает индикаторы пропусков.

Маска вычисляется до замены NaN нулями. Модель использует последний допустимый
временной шаг. Если исключена вся последовательность, используется нулевое
представление.

## Входные данные, эпохи и восстановление

Worker восстанавливает `indexedFeatureBlocks` порциями ограниченного размера
в тензоры `[rows, seqLen, featureDim]`. Разбиение передачи на пакеты и чанки не
определяет батчи оптимизатора, перемешивание строк или границы эпох. Обучение
может начаться после поступления данных. Закрытие входа отмечает конец загрузки
и фиксирует манифест данных для последующих полных эпох.

Контрольные точки для восстановления создаются только после завершения
глобальной эпохи и окончания загрузки данных. Они хранят модель, оптимизатор,
AMP scaler, состояние генераторов случайных чисел, перемешивания и выбора
эпохи, прогресс, идентификаторы совместимости, конфигурацию задания и хеш
манифеста входных данных. Перед загрузкой состояния проверяется их точное
совпадение. Изменение определения данных, модели или манифеста отклоняется;
перестановка целей и частичная загрузка состояния не выполняются.

Состояния CPU RNG и перемешивания восстанавливаются на CPU и при исполнении на CUDA;
состояния CUDA RNG также передаются генераторам как CPU ByteTensor.

Восстановление применяется только при допускающем повтор сбое Worker, пока
сервис продолжает работать. При любом перезапуске сервиса все незавершённые
задания завершаются до запуска WorkerPool: `WAITING_INPUT`, `QUEUED`, `RUNNING`
и `RETRYING` получают `FAILED / EXECUTION_INTERRUPTED`, а `CANCELLING` —
`CANCELLED`. Новый процесс сервиса не возобновляет эти задания из контрольных
точек.

Временные файлы попытки управляются сервисом. При старте он очищает только
свои заблокированные рабочие каталоги и удаляет файлы, на которые больше нет
ссылок. Каталоги другого экземпляра Transformer он не проверяет и не очищает.

## Показатели обучения и диагностика

Метрики эпохи собираются во время обучающего прохода перед обновлениями
оптимизатора. Это значения потерь, обучающие MAE/RMSE, счётчики состояния
обучения и, если включено, взаимодействия градиентов. Ошибки сохранения метрик
не меняют работу оптимизатора, выбор эпохи, успех задания или публикацию модели.

Сервис отправляет копию метрик в OpenSearch. Клиент получает проверенный отчёт
через API показателей обучения. Отсутствие отчёта не означает, что
опубликованная модель некорректна.

При явной `diagnostics.targetHead = "fullCommittedArtifact"` Worker после
каждой завершённой эпохи выполняет отдельный наблюдательный проход по полному
зафиксированному набору входных данных в `eval()` и `torch.no_grad()`. Он
сохраняет только агрегаты исходных логитов, публичных предсказаний,
представлений до энкодера, после каждого его слоя и перед выходной головкой,
градиента прямой компоненты и параметров головки. Формат диагностики v5 также
сохраняет значения на этапах `input`,
`attentionResidual`, `norm1`, `feedForwardResidual`, `norm2` каждого
слоя энкодера и `linear`, `gelu`, `layerNorm` блока `OutputHead.shared`.
Порядок задаётся неизменяемым `encoderNormalizationOrder`. Диагностика и ошибки
её сохранения не меняют веса, оптимизатор, RNG, метрики эпохи или результат
`predict`. Без указанной настройки диагностический файл не создаётся.

При дополнительной `diagnostics.encoderLayerDiagnostics =
"directComponentPerBatch"` файл также содержит градиенты прямых компонент
и нормы обновлений групп `attention`, `feedForward` и `normalization` каждого
слоя энкодера. Точный состав групп, этапов прямого прохода и правила обработки
отсутствующих или неконечных наблюдений описаны в
[спецификации диагностики](../app/contracts/target_head_diagnostics/v5/README.md).

## Переход на Semantic v7

Миграция `0031` удаляет задания и модели предыдущего формата. Worker не читает
их контрольные точки и состояние восстановления. Текущий сервис использует
индексы метрик v13 в OpenSearch. После миграции для диагностики нужно обучить
новые модели с включёнными настройками наблюдений.

## Confidence penalty

Необязательный `BernoulliConfidencePenalty` использует публичную вероятность
существующей цели и передаёт градиент той же головке. Новый внутренний ресурс
или изменяемое состояние для этого не создаются. Оператор и его вес задаются
в определении функции потерь. Восстановление и обучение от опубликованной
модели проверяют точное совпадение определения; смена веса означает другую
функцию потерь.

Вклад регуляризатора виден во вспомогательных потерях и взаимодействиях
градиентов. Выбор эпохи и диагностика прямых компонент работают как прежде.

## Entropy penalty

Необязательный `BernoulliEntropyPenalty` минимизирует положительную энтропию
той же публичной вероятности: `BCE + lambda * H(p)`. Оператор использует логит
с поправкой на вес класса и устойчивый расчёт без обрезки вероятности или
отключения градиента. Float16/bfloat16 переводятся в float32 до поправки.
Confidence penalty использует противоположный знак.

Вес задаётся в функции потерь, применяется один раз и входит в определение
модели. Вспомогательные потери показывают положительную среднюю энтропию без
веса; взаимодействия градиентов учитывают взвешенный вклад. Выбор контрольной
точки и диагностика головок используют прямые компоненты. Более крайние
вероятности требуют проверки качества и калибровки на отложенных данных.

## Форматы данных

Текущая версия использует Semantic v7, Flight v24, Worker v22, контрольные
точки v14 и метрики v13. Их назначение и расположение описаны в
[архитектуре](./architecture.md#спецификации-и-версии).
