# Политика зависимостей

> Type: Policy. Этот документ задаёт правила добавления, замены и обновления
> Python-зависимостей.

Новая зависимость допустима только для устойчивой задачи, которую нельзя
разумно закрыть стандартной библиотекой или уже используемым инструментом.

Нужно оценить:

- поддержку и совместимость с Python 3.11+;
- совместимость с PyTorch, PyArrow, SQLAlchemy и Psycopg;
- наличие native extensions, CUDA и системных требований;
- безопасность, лицензию и частоту обновлений;
- стоимость установки на production-хост;
- влияние на import time, память и размер runtime environment.

Нежелательны:

- пакет ради одной простой функции;
- дублирование уже принятой библиотеки;
- wrapper без собственной архитектурной ценности;
- зависимость только ради более короткого синтаксиса;
- скрытая установка системного ПО или CUDA-компонентов.

Например, для файловых операций следует сначала рассмотреть `pathlib`,
`tempfile`, `shutil` и `os`, а для небольших immutable records —
`dataclasses`, прежде чем добавлять пакет.

## Порядок изменения

1. Сформулировать долгосрочную задачу зависимости.
2. Проверить стандартную библиотеку и текущие зависимости.
3. Проверить официальную документацию и совместимость версий.
4. Обновить `requirements.txt`, который является единственным production lock.
5. Выполнить `.venv/bin/python -m pip check` и относящиеся тесты.

Эта политика не разрешает автоматически удалять существующую библиотеку.
Сначала нужно подтвердить отсутствие production, migration, test и
documentation usage по
[Политике жизненности кода](./code-liveness-policy.md).

Установка пакетов в рабочую среду агента или на production-хост выполняется
только с явного разрешения владельца среды.
