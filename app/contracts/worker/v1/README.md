# Transformer worker process contract v1

This directory is the normative internal contract between the Transformer
service process and one short-lived ML worker process. It is independent of the
public Arrow Flight contract.

## Invocation

The service creates and durably closes an immutable command manifest before it
starts a worker without shell interpretation:

```text
transformer-worker run
  --contract-version=1
  --job-id=<uuid>
  --attempt=<positive-integer>
  --attempt-id=<uuid>
  --manifest=<service-controlled-path>
```

The worker validates the arguments, the complete manifest and every referenced
input before training or inference mutates state. `attempt` is the public
positive job-local ordinal. `attemptId` is regenerated by every claim and is
the internal execution identity and equality fence. Ownership is never
transferred while an `attemptId` remains active.

The service discovers installed Torch and CUDA capabilities through the same
process boundary:

```text
transformer-worker inspect --contract-version=1
```

The command emits one validated JSON capabilities document. The service does
not import Torch or initialize CUDA itself.

## Channels

| Channel | Contract |
| --- | --- |
| command/configuration | immutable JSON command manifest |
| input/output data | Arrow IPC files referenced by manifests |
| progress/lifecycle | bounded newline-delimited JSON events on stdout |
| diagnostics | stderr |
| terminal transport | process exit status |

Worker v1 pins the Arrow artifact schema identifiers carried from Flight v2:
`inventory.sequence.fit.v1`, `inventory.sequence.predict.v1` and
`transformer.prediction.v1`. Changing the public transport contract does not
implicitly change worker v1; a different mapping requires an intentional
process-contract revision.

Stdout contains only worker event envelopes. One complete event occupies one
line and is flushed before the next event. Events are strictly sequenced from
one and carry `jobId`, numeric `attempt` and `attemptId`. The service accepts an
event only for the currently active equality fence and for a state permitting
that event's mutation.

## Artifact lifecycle

The worker writes only below its attempt workspace. It closes and fsyncs an
artifact before emitting an event containing its path, byte count and SHA-256.
It cannot publish a recovery generation, prediction output or model reference.

The service validates every staged artifact, publishes it into a service-owned
immutable namespace, fsyncs that namespace and only then records its reference
in PostgreSQL. A crash may leave an unreferenced artifact, never a database
record pointing at an incomplete file. Reconciliation removes unreferenced
staging artifacts after retention.

## Exit semantics

- `completed` followed by a valid result manifest and exit `0` is eligible for
  service publication;
- exit `0` without exactly one `completed` event is a protocol violation;
- `completed` followed by a non-zero exit is a protocol violation;
- a non-zero exit without a valid safe `error` event is
  `SUBPROCESS_FAILED`;
- failure to stop within the service deadline is `SUBPROCESS_HUNG`;
- cancellation and worker failure are arbitrated by the service state policy;
  cancellation does not silently rewrite an already observed internal failure.

An old process is never reattached after service recovery. Its attempt is
closed and a retry, when policy permits it, receives a new numeric attempt and
new `attemptId`.
